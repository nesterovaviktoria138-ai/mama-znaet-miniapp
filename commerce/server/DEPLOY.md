# Пакет запуска сервера

Статус: подготовлен в GitHub; внешний сервер ещё не создан и не оплачен.
Продажи остаются программно заблокированы. Не подключайте webhook до проверки
хостинга и процедуры сохранения/восстановления покупок.

## Что нужно от владельца

Название существующего хостинга или выбор нового, согласование его тарифа.
Токен бота вводится только в закрытом поле секретов хостинга — не в переписке.
GitHub Pages не исполняет Python-сервер. Этот пакет не меняет адрес Mini App.

## Совместимый хостинг

Linux Docker, исходящий HTTPS к api.telegram.org, входящий HTTPS, постоянный
диск с резервными копиями. Один экземпляр сервиса, два WSGI-процесса используют
один файл SQLite. Не масштабировать на несколько машин с разными дисками.
Хостинг и регион хранения требуют выбора владельца до создания платного ресурса.

Сборка из корня репозитория:

```sh
docker build -f commerce/server/Dockerfile -t mama-payments .
```

Параметры сервиса:

| Настройка | Значение |
|---|---|
| Repository | nesterovaviktoria138-ai/mama-znaet-miniapp |
| Branch | main |
| Dockerfile | commerce/server/Dockerfile |
| Build context | корень репозитория |
| Port | 10000 (либо PORT хостинга) |
| Health check | /health |
| Persistent volume | /var/lib/mama-payments |
| PAYMENTS_DB | /var/lib/mama-payments/payments.sqlite |

Том должен разрешать запись UID/GID `10001:10001`. Если платформа монтирует его
с владельцем root, настройте права тома средствами платформы до запуска.
Не переводите приложение в root только для обхода проблемы с правами.

Обязательные секреты:
- TELEGRAM_BOT_TOKEN: полный токен собственного бота из BotFather.
- TELEGRAM_WEBHOOK_SECRET: случайная строка минимум 32 символа из A-Z, a-z,
  0-9, _ и -. Генерируется в защищённой среде хостинга.

TERMS_VERSION понадобится перед подключением интерфейса покупки. Публичный
каталог сохраняет stars=null и sales_enabled=false. Реальные цены не заданы.

## Проверка после размещения

1. `/health` возвращает ok=true, sales_enabled=false.
2. POST `/telegram/webhook` без секрета отклоняется.
3. POST `/api/access` без подписи Telegram отклоняется.
4. Создание счёта заблокировано; никаких списаний нет.
5. Перезапуск сохраняет базу на подключённом диске.
6. Настроены HTTPS, ограничение тела запроса 64 КиБ, ограничения частоты
   и времени чтения на входном прокси. Access logs приложения выключены;
   проверьте также журналы хостинга, чтобы они не сохраняли тела и секреты.
7. Сделана согласованная резервная копия SQLite через backup API и проверено
   восстановление. Копия на том же диске не защищает от потери самого диска.

Далее нужен список предзапусковых задач из README.md: защищённая выдача материалов,
поддержка покупок, условия, цены Stars, возвраты оператора и тесты Telegram.

## Проверено локально

12 тестов логики платежей и запуск WSGI через Gunicorn с вымышленными секретами.
Сборка Docker и развёртывание на внешнем хостинге требуют отдельной проверки;
Docker в текущей рабочей среде отсутствует.
